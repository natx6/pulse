# Pulse — Tier 1–3 Gap Implementation Plan

> **For Hermes:** This is a cross-session handoff plan. The user starts a fresh
> chat and says "execute the plan at .hermes/plans/<this-file>". Execute it
> task-by-task; commit + push to github.com/natx6/pulse after each tier.

**Goal:** Close the audited gaps: refunds/returns/void, stock adjustments,
restore-from-backup + rotation, operator report filter, daily cash-up,
barcode label printing, patient history, Tier-3 polish — AND simplify the
navigation from three overlapping stock surfaces to two clear ones
(Inventory = see + receive; Requisitions = order).

**Architecture:** Tauri 2 + React + Zustand + SQLite. All money/stock mutations
are atomic Rust commands (rusqlite transactions). Schema changes go through the
OWN migration runner in `src-tauri/src/lib.rs` (`run_migrations`, PRAGMA
user_version, idempotent, `const MIGRATIONS: &[(&str, &str)]`).

**Tech Stack:** react, zustand, @tauri-apps/api, @tauri-apps/plugin-sql,
tailwind. NO new deps (hard rule). No test framework — verification is
`npm run build` + `cargo check` + ad-hoc `/tmp/hermes-verify-*.py` scripts
against real SQLite + live-DB inspection.

## Non-negotiable project conventions (the new session MUST know these)

1. **DB location quirk**: tauri-plugin-sql resolves `sqlite:pulse.db` to the
   app CONFIG dir = `~/.config/com.pulse.pharmacy/pulse.db` on Linux.
   Every Rust command uses `app.path().app_config_dir()` — NEVER data dir.
   Live DB currently at `user_version = 6` (migrations 0001–0006 applied).
   Backups live in `backups/` beside it, exports in `exports/`.
2. **Migration runner**: add new migrations to the `MIGRATIONS` const in
   lib.rs (`("0007_xxx", include_str!("../migrations/0007_xxx.sql"))`) —
   the runner handles application + idempotency. Always `INSERT OR IGNORE`
   for seeds/settings defaults. `DROP TABLE IF EXISTS` is safe for leftovers.
3. **Verification ritual** (every tier, evidence required):
   - `npm run build` (tsc + vite) — must pass, note gzip size (~68.8KB now).
   - `cargo check` in src-tauri — must pass.
   - Ad-hoc python script `/tmp/hermes-verify-<name>.py` against a fresh
     in-memory DB running ALL migrations + the exact SQL/logic being added.
   - Check the LIVE DB with `python3 -c "import sqlite3..."` when relevant
     (user_version, new tables).
   - **Gotcha**: running `cargo check` while the `npm run tauri dev` watcher
     is active holds the build lock and stalls the watcher's rebuilds — after
     Rust edits, prefer letting the watcher rebuild, or restart the dev
     session. Hotspot network throttles npm/crates.io: npm
     `--fetch-timeout=900000`, cargo `CARGO_HTTP_LOW_SPEED_LIMIT=1
     CARGO_HTTP_TIMEOUT=600 CARGO_NET_RETRY=10`.
4. **Product/UX rules**: no dead buttons (stub = wire it or remove it); no
   long processes (1–2 taps, no approval workflows); no compliance theater;
   immutable-after-create applies to operators (delete-only, two-step delete
   confirm — mirror this pattern); every sale stamps operator; GHS currency
   everywhere; beep(true)/beep(false) audio feedback on success/error.
5. **Git**: repo `github.com/natx6/pulse` (PRIVATE, main). Commit per task,
   push after each tier. CLI authed as natx6.

## TIER 1 — Money & stock integrity (do first)

### 1.1 Migration 0007: returns

**Files:** Create `src-tauri/migrations/0007_returns.sql`; add to `MIGRATIONS` in lib.rs.

```sql
CREATE TABLE IF NOT EXISTS sale_returns (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  sale_id INTEGER NOT NULL REFERENCES sales(id),
  receipt_no TEXT NOT NULL,
  total_refunded REAL NOT NULL,
  reason TEXT,
  operator TEXT,
  timestamp TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
CREATE TABLE IF NOT EXISTS sale_return_items (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  return_id INTEGER NOT NULL REFERENCES sale_returns(id),
  product_id INTEGER NOT NULL,
  product_name TEXT NOT NULL,
  quantity INTEGER NOT NULL,
  unit_price REAL NOT NULL,
  unit TEXT
);
```

### 1.2 Rust: `return_sale` command (atomic)

**Files:** Modify `src-tauri/src/lib.rs` (+ `#[tauri::command]`, register in invoke_handler).

- Signature: `return_sale(app, sale_id: i64, reason: Option<String>, operator: Option<String>, lines: Vec<ReturnLine>)` where `ReturnLine { product_id, quantity }`.
- Validation (inside one rusqlite transaction):
  - Sale exists; for each line, quantity <= quantity sold in THAT sale
    (`sale_items` where sale_id + product_id).
  - sum(unit_price × qty) = total_refunded.
- Writes: `sale_returns` + `sale_return_items` rows; `UPDATE products SET
  stock_qty = stock_qty + qty` per line. NOTHING touches `sales` (the sale
  stays; reports subtract returns).
- Returns `{ receipt_no, total_refunded, return_id }` so the UI can print a
  return slip.

### 1.3 Rust: `void_last_sale` command (atomic, guarded)

- Signature: `void_last_sale(app, operator: Option<String>)`.
- Guard: only voids the sale with `id = (SELECT MAX(id) FROM sales)` AND
  `date(timestamp) = date('now','localtime')` — today's last sale only.
  Otherwise `Err("Only today's last sale can be voided")`.
- Writes: delete `sale_payments`, `sale_items`, `sale` for that id;
  `UPDATE products SET stock_qty = stock_qty + qty` per item. All in one
  transaction (DELETE order respects FK or use explicit deletes in the right
  order — SQLite FKs are off by default here, but be explicit anyway).
- Returns `{ receipt_no }` voided.

### 1.4 Rust: `adjust_stock` + `list_backups` + `restore_backup` + rotation

**Files:** Modify lib.rs; Create `src-tauri/migrations/0008_stock_adjustments.sql`.

```sql
CREATE TABLE IF NOT EXISTS stock_adjustments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  product_id INTEGER NOT NULL,
  product_name TEXT NOT NULL,
  delta INTEGER NOT NULL,
  reason TEXT NOT NULL,
  operator TEXT,
  timestamp TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
CREATE TABLE IF NOT EXISTS cash_ups (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  day TEXT NOT NULL,
  operator TEXT,
  opening_float REAL NOT NULL DEFAULT 0,
  counted REAL NOT NULL,
  variance REAL NOT NULL,
  timestamp TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
```

- `adjust_stock(app, product_id, delta, reason, operator)`:
  - reason REQUIRED non-empty; delta != 0; new stock_qty must stay >= 0.
  - `UPDATE products SET stock_qty = stock_qty + delta`; insert log row.
  - Atomic.
- `list_backups(app) -> Vec<{ name, size, modified }>`: read `backups/` dir.
- `restore_backup(app, name) -> String`: validate the file is a SQLite DB
  (header check "SQLite format 3\0"), first copy the CURRENT live DB to
  `backups/pre-restore-<timestamp>.db` (safety), then copy the backup file
  over the live `pulse.db`. Return the message; the JS side then calls a
  `restart_app` command (try `app_handle.restart()` — VERIFY it exists in
  tauri v2; if not, fall back to `std::process::exit(0)`? NO — use
  `app_handle.restart()` if available, else return "Please close and reopen
  Pulse").
- **Backup rotation**: inside the existing auto-backup path (`backup_db`),
  after writing a new backup, prune `backups/` to keep the newest 20 files
  (sort by name — filenames are timestamped). Best-effort like the rest of
  the backup path; never fail a sale because of pruning.

## Risks / open questions

- `AppHandle::restart()` availability in tauri v2 — verify in plugin source;
  fallback is an explicit "close and reopen Pulse" message (acceptable).
- Sales schema patient linkage — READ 0001_init.sql before writing the
  patient history query (patient_id FK vs name column).
- Void semantics: restricted to today's last sale by design (history
  integrity). If the user wants full void freedom later, that's a separate
  decision — the return path covers everything else.
- Restore swaps the DB file under a live connection: do the copy FIRST, then
  restart — never write through the old connection after the swap.
